  • Tra cứu danh sách đề thi theo danh mục.
  • Làm bài thi trực tuyến: Đồng hồ đếm ngược, lưu tạm trạng thái bài làm.

  • Xem lại lịch sử thi đã thực hiện.
👨‍🏫 Dành Cho Giáo Viên
  • Quản lý đề thi (Tạo mới, chỉnh sửa, xóa đề thi).
  • Vòng đời đề thi: DRAFT → PUBLISHED → ARCHIVED.
  • Sinh câu hỏi AI tự động theo chủ đề/đoạn văn bản bài học.
  • Duyệt / Từ chối câu hỏi do AI sinh.
  • Thêm câu hỏi thủ công truyền thống.
  • Xem thống kê điểm TB, tỷ lệ đạt của từng đề.
⚙️ Quản Trị Viên (Admin)
  • Toàn quyền quản lý mọi đề thi trong hệ thống.
  • Quản lý tài khoản người dùng (Khóa / Kích hoạt).
  • Phân quyền hệ thống (STUDENT / TEACHER / ADMIN).
  • Theo dõi nhật ký gọi AI (AIGenerationLogs).
  • Thống kê toàn diện danh sách bài nộp và phổ điểm tổng thể trường học.

08. Giao Thức Mạng

Các Giao Thức Mạng Áp Dụng (Mô Hình TCP/IP)

Phân tầng và cơ chế vận chuyển dữ liệu từ phần mềm người dùng đến tầng vật lý.

📦 Phân Tầng Giao Thức Trong QuizAI
Tầng Ứng Dụng (Application) HTTP / HTTPS
Truyền tải JSON payload giữa React và ASP.NET Core
Tầng Truyền Vận (Transport) TCP (Transmission Control)
Đảm bảo truyền tin tin cậy, không mất gói khi nộp bài thi
Tầng Mạng (Network / Internet) IPv4 / IPv6 + ICMP
Định tuyến gói tin IP giữa các host mạng nội bộ/Internet
Tầng Liên Kết & Vật Lý Ethernet / Wi-Fi (802.11)
Mã hóa bit truyền qua dây cáp hoặc sóng vô tuyến
🤝 Tại Sao Phải Dùng TCP Thay Vì UDP?
Trong ứng dụng thi trắc nghiệm online, tính chính xác và toàn vẹn của dữ liệu là tiên quyết:
  • Không chấp nhận mất gói: Một câu trả lời hoặc câu hỏi bị rớt gói tin sẽ làm sai lệch hoàn toàn kết quả thi của học sinh.
  • Thứ tự gói tin: TCP đảm bảo các phân đoạn (segments) được ghép lại đúng thứ tự đã gửi.
  • Cơ chế báo nhận (ACK) & Retransmission: Tự động truyền lại phân đoạn bị lỗi trên đường truyền mạng.
Cơ chế bắt tay 3 bước TCP (3-Way Handshake)
Client
1. SYN (seq = x)
Server
Client
2. SYN-ACK (seq = y, ack = x+1)
Server
Client
3. ACK (ack = y+1) [ESTABLISHED]
Server

10. An Ninh Mạng

HTTPS: Cơ Chế Hoạt Động & Bảo Mật TLS/SSL

Bảo vệ tính bí mật và toàn vẹn dữ liệu bài thi trước các cuộc tấn công mạng.

🔐 Bản Chất Của HTTPS (HTTP over TLS)

HTTPS là sự kết hợp giữa HTTP (Tầng ứng dụng) và giao thức TLS (Transport Layer Security) chạy trên cổng mặc định 443.

  • Chống nghe lén (Sniffing): Dữ liệu mật khẩu, đề thi và câu trả lời được mã hóa, kẻ tấn công dùng Wireshark chỉ thấy chuỗi byte ngẫu nhiên.
  • Chống giả mạo (Data Tampering): Mã xác thực thông điệp MAC (Message Authentication Code) kiểm tra tính nguyên vẹn.
  • Chống tấn công giả mạo (Man-in-the-Middle - MitM): Chứng chỉ số SSL/TLS do cơ quan chứng thực (CA) cấp chứng minh danh tính Server.
⚡ Quy Trình Bắt Tay TLS Handshake
Client
1. Client Hello (TLS version, Cipher Suites)
Server
Client
2. Server Hello + Certificate (Public Key)
Server
Client
3. Xác thực Cert + Key Exchange (Pre-Master Secret)
Server
Client
4. Finished (Mã hóa Session Key đối xứng AES)
Server

★ Tối ưu hóa: Dùng mã hóa bất đối xứng (RSA/ECC) để trao đổi khóa, sau đó dùng mã hóa đối xứng (AES-GCM) để truyền dữ liệu bài thi tốc độ cao.

11. Xác Thực & Kiểm Soát Truy Cập

Cơ Chế Xác Thực JWT & Chính Sách Mạng CORS

Bảo vệ tài nguyên API thông qua cơ chế chữ ký số không trạng thái (Stateless Token).

🎫 Cấu Trúc & Xác Minh JSON Web Token (JWT)
Header (Thuật toán HS256) .
Payload (UserId, Username, Role: STUDENT/TEACHER/ADMIN) .
Signature = HMAC-SHA256(Header + Payload, SecretKey)
  • Client nhận JWT khi Login thành công và lưu vào localStorage.
  • Gửi kèm trong HTTP Header: Authorization: Bearer <Token>.
  • Backend dùng Secret Key đối chiếu chữ ký để xác thực mà không cần truy vấn lại Database, giảm tải tải mạng vượt trội.
🛡️ Giải Quyết Bài Toán Mạng: CORS & Reverse Proxy
Trình duyệt thực thi Same-Origin Policy ngăn chặn Client (Port 5173) gọi trực tiếp Backend (Port 5000):
Cách 1: Cấu hình CORS Middleware trong ASP.NET Core
Khai báo app.UseCors() cho phép http://localhost:5173 với đầy đủ Header và Method.
Cách 2: Vite Reverse Proxy (Triển khai chính)
Mọi request /api/* từ React được Vite Proxy ngầm chuyển tiếp sang http://localhost:5000, triệt tiêu lỗi CORS.

14. Luồng Dữ Liệu (Data Flow)

Luồng Dữ Liệu 3: Làm Bài Thi & Chấm Điểm Thời Gian Thực

Cơ chế đồng bộ thời gian và xử lý nộp bài an toàn không gian lận.

⏱️ Bước 1: Khởi Tạo Bài Thi & Đồng Bộ Thời Gian

Học sinh nhấn Bắt đầu làm bài:

  1. Client gửi POST /api/submissions/start kèm examId.
  2. Server tạo record Submissions với StartedAt = DateTime.UtcNow và trạng thái IN_PROGRESS.
  3. Server tính toán và trả về RemainingSeconds dựa trên đồng hồ Server, tránh việc học sinh chỉnh giờ máy tính cục bộ để gian lận.
📊 Bước 2: Nộp Bài & Tính Điểm Tức Thì

Học sinh nhấn Nộp bài hoặc Đồng hồ đếm ngược chạm 00:00:

  1. Client gửi POST /api/submissions/submit chứa danh sách các đáp án đã chọn.
  2. Server duyệt từng câu, đối chiếu IsCorrect từ bảng Options.
  3. Công thức điểm: TotalScore = (Số câu đúng / Tổng số câu) * 100.
  4. Cập nhật trạng thái COMPLETED và trả về kết quả kèm lời giải thích chi tiết.
🛡️ Cơ chế phục hồi sự cố mạng (Fault Tolerance)

Nếu học sinh vô tình bị mất mạng, rớt mạng hoặc đóng trình duyệt, khi vào lại đề thi, hệ thống sẽ tự động nhận diện bài nộp cũ đang IN_PROGRESS, tính toán trừ đi thời gian đã trôi qua và cho phép học sinh tiếp tục làm bài thi mà không bị mất dữ liệu.
